# 帕金森运动量化评估系统

门诊运动障碍评估的可复算证据链系统。解决的核心临床问题：**两次复诊的震颤分数下降，可能只是服药相位不同、动作提示节拍版本不同造成的——数字本身不能支持调药。** 系统把协议偏差与真实变化分开，让每一个分数都能追溯到试次、信号区间与处理版本，并在跨访视比较时明确给出「可比 / 不可比」及原因。

## 临床不变量

1. **原始证据不可变且可复算**：采集端导出经规范化生成内容寻址的输入清单（源文件 sha256、每条原始记录与规范化试次 sha256、信号 blob sha256）。算法运行前逐项校验，任何字节篡改都会被拒绝。
2. **双腕时钟不强行对齐**：设备侧时钟只通过各自的同步脉冲锚定到临床时间。同一临床脉冲在左/右腕读数相差 160ms 时，保留这 160ms 真实偏移，而不是假装同步。
3. **不拼接左右腕 / 不跨方案比较**：指标按 `(任务, 佩戴侧)` 组织，同组至多入选一个试次；v2 缺右腕步行试次时标记「复诊无有效试次」，绝不用左腕顶替。
4. **版本化运行、新老结果并列**：run 与指标由 `算法版本 + 参数版本 + 输入清单 + 试次` 内容寻址，`createdAt` 不参与身份。同一输入重算得到相同 ID（安全幂等）；新算法（如 1.0.0 单轴 → 1.1.0 三轴合成）产生并存的新结果，不覆盖旧结果。
5. **协议偏差与采用结果分开**：治疗师的复核决定（排除片段 `exclude`、确认补做 `confirm-make-up`、保留 `include`）单独留痕。中断试次进入摘要的「排除清单」；补做试次只有经确认才以 `confirmed-make-up` 入选。
6. **签署内容不随重算变化**：临床摘要按规范化 JSON 字节进行 Ed25519 签署，载荷字节随签名一起冻结。之后无论怎样重算，已签署内容与验签结果不变；篡改载荷即验签失败。
7. **跨访视比较先对齐再下结论**：只有在佩戴侧、双方有效试次、提示（节拍）版本、方案规格、服药相位（默认 ±30 分钟，参数化）、算法/参数版本全部一致时才给出 `deltaScore`。不可比时仍展示 `rawDeltaScore`（原始分数差），但同时列出原因且 `deltaScore = null`——可见数字，但不能当疗效证据。

## 数据链路

```
fixtures/motor-assessments.json（原始导出：双腕不同步/中断/补做）
  └─ ingest.ts        设备时钟→临床时钟（同步脉冲锚定）、确定性合成信号段、输入清单
       └─ algorithm.ts 引用清单哈希 + 参数版本，Goertzel 频带分析，双算法版本并存
            └─ clinical.ts  治疗师复核 → 临床摘要 → Ed25519 签署（字节冻结）
                 └─ comparison.ts 对齐相位/提示/侧别/处理版本，输出可比与不可比原因
                      └─ registry.ts 分数 → 试次 → 信号区间 → 处理版本/清单 的追溯链
```

## 领域结构

`src/contracts.ts` 定义全部类型：方案版本（静息/姿势/旋前旋后/步行四段）、试次（设备时钟、同步脉冲、佩戴侧、执行偏差、状态）、输入清单、参数集、派生指标、复核、临床摘要、签名、跨访视报告。

## 运行

```bash
npm test      # tsc 类型检查 + 编译 + 端到端自检（23 项断言）
npm start     # 运行已编译的演示，产物写入 out/
```

`out/` 下生成：
- `input-manifest.json`：不可变输入清单；
- `signed-summary-v2.json`：v2 复诊的已签署临床摘要（含冻结载荷与签名）；
- `comparison-v1-v2.json`：跨访视比对报告。

## fixture 场景（两次访视）

- **v1**（方案 v2，服药后 60 分钟）：双腕四段完整。
- **v2**（方案 v3，服药后 95 分钟）：静息/姿势/旋前旋后完成；步行首试 `v2-walk-a` 因遇障碍中断（12/30 秒），补做 `v2-walk-b` 完整但为左腕；姿势段有咳嗽偏差；方案 v3 把旋前旋后节拍从 metronome-v1 改为 v2。

因此示例报告中：静息分数虽从 41.01 降到 22，但因服药相位相差 35 分钟（超 ±30 分钟窗口）判为**不可比**；旋前旋后叠加节拍版本不匹配；右腕步行因复诊无有效试次不可比。另含一个相位完全对齐的构造用例，证明条件齐备时系统会正常给出可比差值。

## 说明

- 信号在演示环境中按试次参数**确定性合成**（mulberry32 种子 + Goertzel 频谱，故峰值频率/幅度可复现）；接入真实系统时将 `synthesizeSegment` 替换为对象存储中的原始二进制读取即可，blob 摘要与区间语义不变。
- 存储为进程内只追加登记处（`AppendOnlyStore`，内容寻址下重放幂等），可替换为事件日志或不可变对象存储。
