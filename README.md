# 帕金森运动量化评估

门诊运动量化评估系统：治疗师发布评估方案，采集端记录双腕试次，算法在不可变输入清单上产出派生指标，医生据此比较不同访视。核心目标是让**协议偏差与真实变化分开**，让每一个分数都能回溯到原始证据。

## 运行

```bash
npm install
npm test        # 类型检查 + 构建 + node:test 测试
npm run demo    # 端到端场景演示（发布方案 → 采集 → 裁量 → 签署 → 比较 → 追溯）
```

运行环境 Node.js 22，语言 TypeScript（strict）。

## 数据流

```
方案版本（pd-motor@2 / @3，发布后不可覆盖）
   │
访视采集（试次：设备时钟 + 同步脉冲 + 佩戴侧 + 执行偏差；信号区间）
   │
时钟对齐（每台设备经各自同步脉冲换算墙钟 → 服药相位分钟数）
   │
治疗师裁量（exclude-segment / exclude-trial / confirm-make-up，版本化）
   │
算法运行（runId 由 算法版本 + 参数版本 + 输入清单哈希 派生）
   │
临床摘要（草稿 → 签署后冻结，contentHash 固定）
   │
访视比较（逐 任务×侧 对齐服药相位与方案规格，标出不可比较原因）
   │
追溯（分数 → 运行 → 输入清单 → 试次 → 信号区间 → 处理版本）
```

## 关键不变量

- **不拼接**：左右腕、不同方案版本的指标绝不合并；比较逐 `任务 × 侧` 成行
  （`compare.ts` 的 `assertAggregatable` 对跨侧/跨方案聚合直接抛错）。
- **可复算**：算法是纯函数；同一输入重算得到同一 `runId` 并安全复用，
  新算法/新参数只追加新运行，与旧结果并列（`runs.ts`）。
- **不可变输入清单**：每次运行登记试次、信号区间、方案、裁量集的内容哈希；
  原始记录被改动会在 `verifyManifest` 复核中暴露（`manifest.ts`）。
- **签署不随重算变化**：摘要签署后深冻结，`contentHash` 只覆盖临床内容；
  重算产生新运行，已签署摘要原样保留（`summary.ts`）。
- **协议偏差显式化**：服药相位差超容差、提示节拍版本/时长不一致、缺少可用
  试次，都会作为 `issues` 标在比较行上，且不给 delta（`compare.ts`）。

## 目录

- `src/contracts.ts` — 领域契约：方案、试次、同步脉冲、信号区间、指标运行、裁量、摘要、比较
- `src/clock-sync.ts` — 设备时钟 → 墙钟对齐，服药相位计算
- `src/manifest.ts` — 不可变输入清单的构建与复核
- `src/metrics.ts` — 算法/参数版本注册表与纯函数指标计算
- `src/curation.ts` — 治疗师裁量（排除片段/试次、确认补做）
- `src/runs.ts` — 只追加的算法运行登记处
- `src/summary.ts` — 临床摘要的构建、签署、校验
- `src/compare.ts` — 访视比较与聚合守卫
- `src/store.ts` / `src/service.ts` — 内存仓储、应用服务与追溯
- `src/ingest.ts` — 采集数据的解析与校验
- `fixtures/motor-assessments.json` — 两次脱敏访视：双腕时钟不同步、步行试次中断与补做、运动伪差片段
- `test/` — node:test 测试（时钟对齐、运行复算、裁量签署、比较追溯）
